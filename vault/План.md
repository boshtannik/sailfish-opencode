# Sailfish-клиент для opencode (Rust + QML)

**Статус:** 🟢 Рабочий прототип на телефоне (2026-09-20): GUI-чаты + сессии, голосовой стек (запись PTT → whisper → STT → авто-отправка), каталог моделей с прогрессом, звуки, персист настроек, `resume` последней сессии. **Де-саботаж выполнен** (commit `b462460`): восстановлены протокольные константы голосового модуля в корневом QML и чистая `GlobalSettingsPage`; `VoiceModelsPage.qml` = полное ТЗ (фильтр языков, сворч. секции Downloaded/Recognition/Synthesis, параллельные загрузки, отмена, выбор, удаление с RemorseItem). Впереди: флоу TTS-озвучки на телефоне, permission-flow, i18n-переводы, Harbour-валидация.
**Цель:** Нативное приложение для Sailfish OS (Xperia 10 IV, aarch64), которое подключается к `opencode serve` и даёт: текстовый чат + PTT (зажал-поговорил → STT) + голосовые ответы (TTS) + живой статус тулов и запросы разрешений.

## Стек
- **Клиент:** Rust (`reqwest` + `tokio`), обёртки типов под `serde` из OpenAPI-спеки opencode.
- **UI:** QML / Silica (Qt 5.5, sil-qt5). Связь Rust ↔ QML: `qmetaobject-rs` (план) — но см. «Rust-шаблоны Sailfish» ниже: есть готовая практика через `qobject-compiler` (проект R1tschY).
- **SSE-стрим:** `/global/event` — единственный источник состояний.
- **STT/TTS:** локальные (whisper.cpp + Piper), **модели скачиваются пользователем через UI** из каталога (как в Speech Note, mkiol/dsnote). **В RPM модели НЕ включаются** — только движки (whisper-cli, piper, opencode) и само приложение.
- **Сборка:** на ноутбуке (не на телефоне!). Целевой таргет `aarch64-unknown-linux-gnu`. Сборка RPM — через Sailfish SDK / `sfdk build` (не qmake: наш бинарь собирается `cargo`, `.pro` только как заглушка для QtCreator/QML-редактирования).
- **opencode serve:** идёт в составе RPM-пакета, запускается сам при старте приложения (RAII). Пользователь ничего не настраивает.
- **Запись/воспроизведение звука:** чистый Rust через `cpal` (ALSA) + `hound` (WAV). Внешних бинарников (arecord/aplay) не требуется; единственная системная зависимость — `libasound.so.2` (есть на любом Sailfish).
- **Язык интерфейса:** en (единственный), но через конфиг i18n — для будущих переводов (язык активен только при 100% заполнении).

## Архитектура
```
QML (Silica UI)
  │   сигналы/свойства (qmetaobject-rs)
  ▼
Rust core (opencode-client)
  ├── api/        — HTTP-клиент к opencode server (reqwest)
  ├── types/      — serde-типы событий, сообщений, permission, session
  ├── state/      — машина состояний (session/tool/permission)
  └── event/      — SSE-стрим, парсер
  │
  ▼
opencode serve  (на телефоне или LAN)
```

## Машина состояний (из OpenAPI-спеки)

### Сессия
- `idle` | `busy` | `retry { attempt, message, next }`

### Тул
- `pending` (ждёт input) → `running` → `completed { output }` | `error { error }`

### Разрешения (permission)
- `permission.updated` (запрос от сервера)
- Варианты ответа — ровно то, что сервер прислал (не придумываем)
- Ответ шлётся: `POST /session/:id/permissions/:permissionID { response, remember? }`

### Сообщения
- user/assistant + ошибки (ProviderAuth, Api { retryable }, Aborted, OutputLength, Unknown)

### События SSE (полный список)
`server.connected`, `session.created|updated|deleted|diff|error|status|idle|compacted`,
`message.updated|removed`, `message.part.updated|removed`, `permission.updated|replied`,
`file.edited`, `todo.updated`, `command.executed`, `file.watcher.updated`, `vcs.branch.updated`, `pty.*`, `tui.*`

## План: активность тулов в UI (2026-10-14)

**Проблема:** во время работы агента лента молчит. События тулов (`session.next.tool.*`, `session.next.shell.*`) в диспетчере не обрабатываются (72 «ignored»), а `ToolStore` хоть и заполняется по старому пути (`message.part.updated` → `Part::Tool`), но QML его никогда не читает: `bridge.tools_json()` не вызывается, полоса тулов отсутствует (настройка «Show tools strip» — мёртвая).

**Цель:** видеть, чем занят агент: bash / браузер (webfetch) / read / edit и т.п. — компактная полоса активности текущего хода.

**Шаги:**
1. **Backend — события.** В `event/dispatcher.rs` завести ветки для всех `session.next.tool.*` (input.started/delta/ended, called, progress, success, failed) и `session.next.shell.started/ended`; обработчики маппят их в `ToolStore` (`state.tools`).
2. **ToolStore — порядок и хелперы** (`state/tool.rs`): хранить порядок появления (`order: Vec<String>`), добавить `ensure/set_state/name_of/clear`; `clear()` вместо прямого `states.clear()` (main.rs, 5 мест).
3. **ToolState — частичный input** (`types/tool.rs`): `description()` понимает строковый input (поток аргументов tool-call, `input.delta`).
4. **Snapshot** (`main.rs::refresh_tools_json`): отдавать тулы в порядке появления.
5. **QML.** В `poll()` читать `bridge.tools_json()` → `app.tools`; в `ChatPage.qml` — полоса чипов (статус-точка + имя + описание) между лентой и полем ввода, видима при `showTools && tools.length>0`; цвет: running=highlight, completed=secondary, error=красный.
6. **Сборка релиза → установка на телефон → тест пользователем.**

Отображение: только текущий ход (список чистится на новом промпте и при смене сессии — уже реализовано).

## План: Revert и Fork от сообщения (2026-10-14)

**Задача:** как в TUI — по долгому тапу на сообщении пользователя выбрать «Fork from here» (ветка) или «Revert to here» (откат). Copy уже есть; edit в TUI отсутствует (проверено).

**API сервера (из `/doc` живого сервера 1.19.0):**
- `POST /session/{id}/revert` body `{messageID, partID?}` → откат.
- `POST /session/{id}/unrevert` → вернуть откат.
- `POST /session/{id}/fork` body `{messageID?}` → ветка (у нас `messageID` не передаётся — доработать).
- `GET /session/{id}` → в объекте сессии есть поле `revert {messageID, partID?, snapshot?, diff?}`.

**Семантика отката (из исходников opencode `session/revert.ts`):** `session.revert.messageID` — граница; сообщения с `id >= messageID` скрыты, пока не `unrevert` (или пока не отправлен новый промпт — тогда сервер чистит хвост). Фильтрация — на клиенте (сами сообщения сервер не помечает). `revert` требует `assertNotBusy` — во время работы агента недоступен.

**Скрытая стоимость:** в ленте у строк нет `messageID` (только `[[t:<ms>]]`). Нужно протащить ID через протокол.

**Шаги:**
1. **markers.rs:** маркер ID сообщения `[[m:<id>]]` (хвост user-строки) + `proto_user_line(ts, id, text)`; хелперы. Зеркало в QML.
2. **api/session.rs:** `fork_session(id, message_id: Option<&str>)`, `revert_session(id, message_id)`, `unrevert_session(id)`.
3. **cmd.rs:** `Fork { id, message: Option<String> }` (поле опциональное), новые `Revert { id, message }`, `Unrevert { id }`.
4. **main.rs:**
   - `load_history`: читать `GET /session/{id}` → `revert.messageID`; пропускать сообщения с `id >= revert.messageID`; к user-строкам прицеплять `[[m:<id>]]`.
   - обработчики `Cmd::Fork`/`Revert`/`Unrevert` (перезагрузка истории, `request_nav`).
   - управляющая строка `[[reverted]]<0|1>` в ленту при open/revert/unrevert.
5. **dispatcher.rs:** `on_message_updated` — при `Message::User` для текущей сессии? (нет доступа к current; вместо этого ID прицепляется из истории; живой user-промпт получает ID через отдельную управляющую строку `[[msgid]]<id>` из воркера). *(Решение: живой ID ловим на `message.updated` role=user, шлём control-строку.)*
6. **bridge/app.rs:** qt_methods `fork_from(id, mid)`, `revert_to(id, mid)`, `unrevert_session(id)`.
7. **QML:** `kMsgIdOpen`, `kSetMsgIdTag`, `kRevertedTag`; `msgIdOf(line)`; срезать хвостовой маркер из body; long-press на user-бабле → `ContextMenu` (Fork/Revert); баннер «Вернуть» при `app.reverted`.
8. **i18n:** строки в `.ts`.
9. Сборка релиза → установка → тест пользователем.

**Статус (2026-10-15):** шаги 1–8 реализованы (не закоммичено; в дереве ещё и незакоммиченная фича активности тулов). Сборка релиза `72805177` собрана и установлена, приложение запущено без ошибок QML. Осталось: подтверждение работы пользователем (long-press → меню, Revert → баннер, Restore) и коммит+push. i18n правлены вручную в `harbour-opencode{-ru,-fi,-uk,-de}.ts` (контекст `ChatPage`), т.к. `i18n/qml-src/` больше нет и `lupdate` дал бы большой churn по `<location>`.

**Открытые мелочи:** revert при занятом агенте — прятать меню/баннер (сделано: меню отключено при `busy`); после отправки нового промпта сбрасывать `reverted` (сделано в QML `send()`).
